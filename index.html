Go deeper: brands, architectures, and memory

A brand is not an architecture

NVIDIA is a company. GPU is a processor role. CUDA is NVIDIA’s programming platform. Tensor Cores are specialized units inside supported NVIDIA GPUs. These names describe different layers.

ARM64 and x86-64

These instruction-set families describe how software addresses a CPU. They do not tell you whether a device has a powerful GPU, enough memory, or a supported inference backend.

Shared and separate pools

An integrated GPU may share system memory. A discrete GPU commonly has dedicated VRAM. System RAM and VRAM are not automatically one fully interchangeable pool; offloading can add transfers and constraints.

Training and inference

Training updates model weights and often needs extra memory for gradients and optimizer state. Inference uses learned weights to generate outputs. Our memory lab models inference only.

What this estimate assumes

Raw weight storage = billions of parameters × bits per weight ÷ 8, in decimal GB. We add 10% to weight storage as a teaching allowance for quantization metadata and format overhead. Actual files vary.

You set the runtime and context allowance yourself. This is not a prediction of KV-cache size. The cache depends on layer count, attention design, cache precision, context length, and batch size. OS reserve is another explicit assumption.

We treat the selected memory as one usable pool. Dedicated VRAM and unified memory behave differently. Disk storage and swap do not provide equivalent performance. These are generic examples, not specifications for Micah’s computers.

For real model files and backend support: llama.cpp documentation.
